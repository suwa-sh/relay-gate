# 仕様の還流のあとは、確認済みの受け入れテストの対応づけも追従が要る

前回の学び `20261027_091000_spec-only-reflux-leaves-usdm-acceptance-stale.md`(要求本文と受け入れ基準が古いまま残る)の続き。今回は、要求側は直ったが、実装側の対応づけが古いまま残る向きの事象。

## 何が起きたか

- 還流(feedback run 2〜9)で要求 SPEC-004-04 に受け入れ基準 -12(`{params}` が引数 1 つ全体でない位置)が加わり、-10 の Given の文言も変わった
- uc-map の `atdd_scenarios` は前サイクルで利用者が確認済みの 6 件のままだった。そのまま進めると -12 は CI でも選択実行されず、-10 の step は古い文言に一致しない
- UC 初期化の段で気づき、-12 を対応づけに加えて 7 件にし(利用者には最終レビューで提示)、-10 の step を新しい文言に合わせた

## 原因

- 対応づけは「一度確認したら固定」の扱いで、還流で受け入れ基準が増減・文言変更されたときに見直す手順が無かった
- feature ファイルは bootstrap が再生成するが、uc-map の対応づけと step 定義は再生成の対象外

## 回避方法

- 還流後の UC 初期化で、対象要求の feature のタグ一覧と uc-map の `atdd_scenarios` を突き合わせ、増えたタグ・文言が変わった Scenario を列挙する
- 変わった Scenario の step 定義は、テスト骨格の段で red になるかを先に確かめる

## 次回の対応

- 還流後の再実装では「受け入れ基準の差分(追加・削除・文言変更)」を UC 初期化の確認項目にする
- 対応づけの追加は機械的な追従として記録し、最終レビューで利用者に示す
