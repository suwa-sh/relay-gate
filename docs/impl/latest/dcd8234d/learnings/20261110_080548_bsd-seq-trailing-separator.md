# macOS の `seq -s` は末尾にも区切りを付ける

## 何が起きたか

- 同じキーの重複の期待値 `lines=1,2,...,5000` を作るテストで、`seq -s, 1 N` を使うと macOS(BSD seq)では末尾にカンマが付き、期待値が実装の出力と一致しなかった
- GNU seq(Linux)は末尾に区切りを付けないため、Linux だけで確かめると気づかない

## 原因

- BSD と GNU の `seq -s` の挙動差。区切り文字を「各項目の後」に付けるか「項目の間」に付けるかが違う

## 回避方法

- 行番号の並びなどの期待値は、外部コマンドに頼らず bash だけで組み立てる(`facade/test/usecase/validate_rapid_crosscheck.bats` の 344 行目付近に理由のコメントあり)
- どうしても外部コマンドを使う場合は、macOS と Linux の両方で期待値を出力して比べる

## 次回の対応

- テストの期待値づくりで `seq -s` / `sed -i` / `date` / `stat` などの BSD/GNU 差があるコマンドを使わない
- 既存の学び(macOS では通るが Linux CI で落ちるパターン)と合わせ、逆向き(Linux では通るが macOS で落ちる)もあることを前提にする
