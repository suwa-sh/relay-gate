# 仕様だけの還流で、要求と受け入れ基準が古いまま残る

## 何が起きたか

- 起動コマンドを引数ごとに分けて起動する決まり(2026-10-27 の還流)で、仕様(CLI 契約・spec.md・tier-facade.md)に検証項目の 3 点目「`{params}` は引数 1 つ全体のときだけ」が加わった
- 要求 SPEC-004-04 の本文(「検証は 2 点だけ、引数部分は検査しない」)と受け入れ基準 -10(「引数部分に任意の文字列」)、この UC の API 要約は更新されなかった
- 受け入れテスト(要求から転写した feature)と UC / tier のテスト(仕様から作成)が、同じ入力(`--args={params}`)に対して逆の終了コードを求める状態になった。テスト骨格の作成時に気づき、受け入れテストの fixture を両者が一致する範囲に絞って進めた

## 原因

- 還流の要求が「仕様が直接持つ内容」として扱われ、要求(USDM)と受け入れ基準を見直す範囲に入らなかった
- 要求本文が「2 点だけ」「検査しない」と排他的に言い切っていたため、仕様側で規則を 1 つ足しただけで矛盾になった
- 同じ UC の API 要約は CLI 契約の複製で、複製側の追随を確かめる仕組みが無かった

## 回避方法

- 仕様の還流後にテスト骨格を作るとき、受け入れ基準の Given / Then と仕様の検証ルール・違反文言を 1 件ずつ突き合わせる
- 食い違いがあれば、受け入れテストの fixture を両者が一致する範囲に絞り、その制約を受け入れテストの記録と issue の両方に書く(黙って片方に寄せない)

## 次回の対応

- 仕様に規則を足す還流要求には、要求本文・受け入れ基準・API 要約の追随を完了条件に含める
- 要求本文の「〜だけ」「〜しない」のような排他表現は、仕様に規則を足すたびに見直し対象にする
