# 提案: 前提の照合をサイクルをまたいで内容で行う(dist-impl-feedback / dist-impl-review)

この提案は既存の SKILL.md を変更しない。採否はスキルの保守者が決める。

## 背景

- 仕様の還流後に同じ UC を再実行すると、AssumptionRecord の id が振り直される
- 過去の承認は review_approved event に当時の id で残り、過去の前提ファイルは invalidated/ に移る
- このため、承認済みの前提が「今回新規の仕様の不足」に見える(詳細: `20261111_081622_match-prior-approvals-by-content.md`)

## 提案内容

| 対象 | 提案 |
|---|---|
| dist-impl-feedback の「1. 原因を分類する」 | 現在の前提ごとに、invalidated/ の過去サイクルの前提を文言と target で照合し、「今回新規 / 過去に承認済み / 過去に却下済み」を付ける手順を足す。照合の根拠には review_approved event の assumption_decisions を使う |
| dist-impl-feedback の as-built summary の前提の表 | 「人の判断」の列に、過去の判断の引き継ぎ(当時の id と日付)を書く欄を設ける |
| dist-impl-review(S9) | 過去に承認済みの前提は「引き継ぎの確認だけ」として、判断を求める前提と分けて表示する |
| state-schema(任意) | 前提に、サイクルをまたいで安定する識別子(例: 文言と target の正規化ハッシュ)を持たせる案を検討する |

## 期待する効果

- 利用者に同じ判断を求め直さない
- 承認済みの事項を理由なく要求へ格上げする誤りを防ぐ
