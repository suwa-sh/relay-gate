# 仕様の還流で、完了済みの UC が黙って未追従になる

## 何が起きたか

- この UC の還流(feedback run 2〜9)で、env 形式の設定ファイル全体に共通する規則(空キー行・空白だけの行・同じキーの重複・バイト検査・検査の段・入力の一時複製・制御文字の可視表記)が CLI 契約に入った
- 完了済み UC「feature flag を設定する」の `--feature-flag` はこれに追従しておらず、違反のある設定を終了コード 0 で受理していた。tier BDD も仕様 17 シナリオに対して 9 シナリオ
- これを見つけたのは、この UC の独立検証が範囲外の観察(scope_notes)として実走したからで、計画された経路ではなかった

## 原因

- 還流は「要求を出した UC」を起点に処理され、同じ共通規則を使う完了済み UC の状態(completed)は変わらない
- 共通規則の決定記録(spec-decision-023 / 026 / 028 / 029)には影響 UC が書かれているが、それを完了済み UC の再実行に結びつける仕組みが無い

## 回避方法

- 還流の後、決定記録が挙げる影響範囲のうち completed の UC を列挙し、tier BDD の Scenario 数を仕様と比べる(件数の不一致は未追従の強い兆候)
- 見つけたら、今回の UC の as-built に「他 UC の再実行が必要」として事実を残し、オーケストレータへ伝える

## 次回の対応

- 還流後の最初の UC 初期化で、完了済み UC の仕様 Scenario 数と tier BDD の Scenario 数を機械的に比べる
- 不一致の UC は、今回の UC の完了前に再実行の要否を判断する
