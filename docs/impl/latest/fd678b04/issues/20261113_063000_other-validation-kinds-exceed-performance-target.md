10 秒を超えるのは、ファイルが数 MB になる入力である。

### 原因(feature flag で直した 3 点と同じ形が、他 UC の呼び出し側に残っている)

1. **値ごとの置き換え**: 行ごとに `cli_field_safe_text` を呼んで可視表記を作っている。この関数は bash だけで置き換えるため、
   制御文字の種類が多い値で 1 バイトあたり数マイクロ秒かかる。8 MiB では 20 秒を超える。
   feature flag は、表示の前に値をまとめて `cli_field_safe_text_list` / `cli_field_safe_text_prepare` へ渡す形に直した
   (値の個数によらず sed 1 回。値に 0xC2 があるときは sed 2 回と tr 1 回)。この 2 つの関数は共有ファイル `facade/src/domain/cli_field.sh` にあり、他 UC からも呼べる。
2. **行ごとの文字列操作**: 速報クロスチェック設定の行の読み取り(コメント行の判定・最初の `=` での分割・空白の除去)を
   bash のパターン照合で行っている。1 行が数 MB のとき、行の長さの 2 乗に比例する時間がかかる。
   feature flag は、行の構造の取り出しを sed 1 回に直した(`facade/src/repository/feature_flag_config.sh` の
   `FEATURE_FLAG_CONFIG_NORMALIZE_SED`)。
3. **数十 MB の文字列を bash で写す回数**: 可視表記は元の最大 6 倍になる。行を配列に溜めて写し直すたびに 0.5 秒前後かかる。
   feature flag は、info 行と warn 行を溜めずに最後に書式で出し、大きな値を埋め込む error 行は出すときに可視表記を直接出す形に直した。
   検査の結果をサブシェルで受けるのもやめた(数十 MB を抱えたプロセスの複製に、1 回 0.1〜0.2 秒かかる)。

`--job-map` には、これとは別の制約がある。CSV のセルの解析を bash 単独で行うこと(上の表の 3 行目)が仕様で決まっているため、
制御文字が無くても 8 MiB の 4,999 行に macOS で 11.8 秒かかる(Linux は 4.6 秒)。1 行が数 MB のセルは 60 秒で終わらない。

### 共有関数の中では直せなかった理由

- 値ごとの関数(`cli_field_safe_text`)の中で外部コマンドを起動すると、5,000 行で 5,000 回の起動になり、かえって遅くなる
  (1 回の起動が数ミリ秒)。まとめて渡すかどうかは、表示する値の一覧を知っている呼び出し側でしか決められない。
- 外部コマンドを使うと「補助コマンドの失敗」(終了コード 6)を報告する場所が要る。これも呼び出し側(usecase)の変更になる。
- このため、共有関数には「まとめて置き換える関数」を足すだけにし、値ごとの関数の挙動(出力・外部コマンドを使わないこと・控えの大きさ)は
  attempt 4 のまま変えていない。

## 提案

1. **性能目標の適用範囲を仕様に書く**(S8 / S9 で要求として出す)。
   「5,000 行以内かつ 8 MB 以内を内容によらず 10 秒以内」を、feature flag だけでなく
   4 つの検証種別(`--feature-flag` / `--job-map` / `--rapid-crosscheck` / `--final-crosscheck`)すべてに適用するかを決める。
   推奨: すべてに適用する(2026-09-21 の決定「設定 CSV は 5,000 行・内容によらず 10 秒を共通前提に」と同じ考え方)。
2. **`--rapid-crosscheck`**: feature flag と同じ 3 点を所有 UC で直す。
   行の構造の取り出し(sed)と、キー名をまとめて置き換える流れは feature flag とほぼ同じなので、env 形式の共通の関数にまとめられる。
3. **`--job-map`**: 表示する値(job_id・セルの値・`info: resolved` の行)をまとめて置き換える形に、所有 UC で直す。
   fixed_params の JSON 表記(`"` と `\` の前にバックスラッシュを付ける)は、まとめて置き換える sed に 1 つ置き換えを足せば対応できる。
4. **`--job-map` の CSV の解析**: 「セルの解析は bash 単独」という仕様の制約のまま 8 MB を 10 秒以内にできるかは、
   所有 UC で実測して判断する(macOS では制御文字なしで 11.8 秒)。できない場合は、仕様の制約か性能目標のどちらかを利用者に確認する。

どれも本 UC(feature flag を設定する)の完了条件ではない。本 UC の `--feature-flag` の出力と所要時間には影響しない。
