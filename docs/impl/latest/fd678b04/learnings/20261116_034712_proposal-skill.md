# 提案: CI と同じ環境でのゲートの実行と、前提の記録の精度(dist-impl-bootstrap / dist-impl-implement / dist-impl-verify)

この提案は既存の SKILL.md を変更しない。採否はスキルの保守者が決める。`20261115_180737_proposal-skill.md` までの提案に足すもので、置き換えではない。

## 背景

- 実装の段が開発機(macOS)だけでゲートを通し、独立検証が CI と同じ Linux の lint で失敗を見つけた。実装のやり直しが 1 回増えた(詳細: `20261116_034712_linux-lint-version-gap.md`)
- 同じ前提・同じ仕様に対して、独立検証の判定が回によって「仕様に定めが無い」と「仕様どおり」に分かれた(詳細: `20261116_034712_one-sided-explicit-rule-splits-verdict.md`)
- 層の間だけで使う戻り値の選択が、前提の記録から漏れていた(詳細: `20261116_034712_internal-return-code-missed-in-assumptions.md`)

## 提案内容

| 対象 | 提案 |
|---|---|
| dist-impl-bootstrap の設定 | 「CI と同じ環境でゲートを実行するコマンド」を設定の項目として持つ(例: コンテナのイメージ名と実行の手順)。CI の定義から、道具の版が開発機と違うものを一覧にする |
| dist-impl-implement の実装の段 | 完了の条件に「CI と同じ環境で lint・format・単体テストが通ること」を足す。完了記録に、環境・コマンド・終了コードを書く。実行できないときは理由を書く |
| dist-impl-verify | CI と同じ環境でのゲートの再実行を、検証の必須の手順として明記する(今回は検証者がこれを実行したため、取り込みの前に見つかった) |
| dist-impl-implement の前提の洗い出し | 候補を外す理由に「仕様に明記がある」に加えて「ほかの規則から 1 つに決まる(どの規則か)」を書けるようにする |
| dist-impl-implement の前提の洗い出し | 仕様の終了コードと違う値を返す関数を候補に入れる、という観点を足す |
| dist-impl-verify の判定 | 「仕様どおり」と判定するとき、明記による一致か、ほかの規則からの帰結かを区別して書く。回によって判定が分かれたときに理由を追える |

## 期待する効果

- 開発機と CI の道具の版の違いによる失敗を、実装の段で見つける。やり直しの回数を減らす
- 前提の件数が、読み方の違いで増減しない。最終確認で利用者が見る件数を必要なものに絞る
- 内部の値の選択が記録に残り、後の機能の実装で同じ値を別の意味に使う誤りを防ぐ
