# テストの段を同時に走らせると、関係の無い場面が「入力の複製の失敗」で 1 回だけ落ちる

## 何が起きたか

- 単体テスト(bats)の全件と UC の BDD を同時に走らせたとき、この UC と関係の無い既存の場面が 1 回だけ `error: config snapshot failed`(終了コード 6)で落ちた
- 単独で走らせ直すと通った
- 独立検証でも、独自の入力 320 通りの途中で同じ失敗が 1 回出た。ほかのゲートが終わった後に走らせ直すと 320 通りすべて通った

## 原因

- 原因は特定していない
- 分かっているのは、複数のテストの段を同時に走らせたときだけ起きること、入力を一時ファイルへ複製する工程で起きること、の 2 点である
- 一時ディレクトリの共有か、同時に起動するプロセスの数が関係している可能性がある(未確認)

## 回避方法

- テストの段(単体テスト、tier の BDD、UC の BDD、受け入れ)は 1 つずつ順に実行する。同時に走らせない
- 独自の入力での確認は、ゲートの実行が終わってから行う
- 1 回だけの失敗を見たら、単独で走らせ直した結果を記録する。走らせ直して通った事実と、同時に走らせていた事実の両方を残す

## 次回の対応

- 同時に走らせたときの失敗を再現する手順を作り、原因を特定する(一時ディレクトリを段ごとに分けて再発するかを確かめる)
- 実装の欠陥(複製の工程が、同時に動く別のプロセスの影響を受ける)であれば、入力の複製を持つ UC の中で直す。環境の制約であれば、開発規約に「段は 1 つずつ実行する」と書く
