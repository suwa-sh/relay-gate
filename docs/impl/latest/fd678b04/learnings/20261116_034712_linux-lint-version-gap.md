# macOS の新しい ShellCheck で通っても、CI と同じ版(0.9.0)では落ちる診断がある

## 何が起きたか

- 実装の段は macOS だけで 4 つのゲートを実行し、すべて通った(ShellCheck 0.11.0)
- 独立検証が CI と同じ Ubuntu 24.04 のコンテナで lint を実行すると、終了コード 1 になった(ShellCheck 0.9.0)
- 診断は 2 件。省略できる引数を持つ関数の定義に SC2120、その関数を引数なしで呼ぶ行に SC2119
- 実行時の不具合ではないが、CI の必須のゲートが通らないため、実装をもう 1 回やり直した

| 環境 | ShellCheck | lint の結果 |
|---|---|---|
| macOS(開発機) | 0.11.0 | 通過 |
| Ubuntu 24.04 のコンテナ(CI と同じ) | 0.9.0 | 失敗(SC2120 / SC2119) |

## 原因

- CI は `apt-get install shellcheck` で入る版を使う。Ubuntu 24.04 では 0.9.0 で、開発機の版より古い
- 同じコードでも、版によって出る診断が違う。新しい版で通ることは、古い版で通ることを意味しない
- 実装の段の完了条件が「開発機でゲートが通ること」だけで、CI と同じ版での実行を含んでいなかった
- 直前の回までは Linux のコンテナで単体テストを実行していたが、今回の 1 回目は実行していなかった

## 回避方法

- 実装の段で、開発機のゲートに加えて、CI と同じコンテナ(`relay-gate-ci:ubuntu24`)で lint・format・単体テストを実行する
- コンテナには、リポジトリを読み取り専用でマウントし、コンテナ内の一時ディレクトリへ複製してから実行する(共有マウント上では実行権限の判定が変わるため)
- 省略できる引数を持つ関数は、呼び出し側で既定と同じ値を明示して渡す。診断の抑制は使わない
- 関数の引数を無条件に転送する書き方(`"$@"`)は、別の意味の引数を渡してしまうことがあるため使わない

## 次回の対応

- 実装の段の完了記録に、Linux での実行結果(環境・コマンド・終了コード)を必ず書く。実行していない場合は、その理由を書く
- コンテナのイメージに node と shfmt を入れ、tier の BDD と format も Linux で実行できるようにする(今回 shfmt は別に取得して使い、tier の BDD は Linux で実行していない)
- CI の ShellCheck の版を固定するか、開発機の版を CI に合わせるかを、利用者に相談する
