# 提案: 方針資料に無い規則の洗い出しと、未公開の下書きの更新(dist-spec / dist-impl-bootstrap / dist-impl-implement / dist-impl-feedback)

この提案は既存の SKILL.md を変更しない。採否はスキルの保守者が決める。`20261115_145719_proposal-skill.md` の提案に足すもので、置き換えではない。

## 背景

- 仕様の初回生成時に足された「runner / worker の 4 キーは絶対パス必須」が、方針資料の設定例(相対パス)と食い違っていた。理由の記録が無く、サンプルを置こうとするまで約 2 か月半見つからなかった(詳細: `20261115_180737_spec-rule-absent-from-policy-docs.md`)
- 作業ディレクトリを基準にするパスのテストで、環境変数 PWD を渡さないと macOS でだけ字面が食い違った(詳細: `20261115_180737_logical-pwd-in-path-tests.md`)
- テストの段を同時に走らせると、関係の無い場面が 1 回だけ落ちた(詳細: `20261115_180737_concurrent-test-runs-snapshot-failure.md`)
- 未公開の下書きがある状態で、仕様の更新による再実行が入った。下書きの更新のきっかけは利用者の回答ではなく、新しい検証結果だった

## 提案内容

| 対象 | 提案 |
|---|---|
| dist-spec の仕様の生成 | 入力の資料に対応する記述が無い規則(検査・拒否・必須)を足すときは、理由を判断記録に書く。理由を書けない規則は足さず、未決事項として記録する |
| dist-spec の BDD の生成 | 入力の資料にある設定例・コマンド例を、字面のまま入力にした場面を 1 つ以上作る |
| dist-impl-bootstrap | 実装を始める前に、「入力の資料に無く、理由の記録も無い規則」の一覧を作り、利用者へ見せる手順を足す。利用者は各行を「資料へ戻す」「理由を記録して残す」に振り分ける |
| dist-impl-implement のテストの足場 | 作業ディレクトリを指定して起動する補助関数は、環境変数 PWD も合わせて渡す、という注意を足す |
| dist-impl-implement / dist-impl-verify のゲートの実行 | テストの段は 1 つずつ順に実行する、と明記する。1 回だけの失敗は、単独で走らせ直した結果と、同時に走らせていた事実を記録する |
| dist-impl-feedback の mode の表 | `refresh` の説明に「未公開の下書きがある状態で入力(検証結果・前提)が変わったとき」を足す。現在の説明は利用者の回答の反映だけを挙げている |

## 期待する効果

- 仕様が方針資料から離れた箇所を、実装の前に見つける。実装とテストのやり直しを減らす
- 環境の違いによるテストの食い違いを、実装の欠陥と取り違えない
- 未公開の下書きの番号と作成時刻を保ったまま、新しい検証結果へ追従できる
