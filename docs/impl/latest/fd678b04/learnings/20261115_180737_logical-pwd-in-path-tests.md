# 作業ディレクトリを基準にするパスのテストは、環境変数 PWD を渡さないと期待する字面と食い違う

## 何が起きたか

- 相対パスの設定ファイルを絶対パスにするとき、仕様は作業ディレクトリを「シェルの `$PWD` の論理パス(シンボリックリンクを辿らない)」と定めている
- テストから作業ディレクトリを指定してコマンドを起動したとき、環境変数 PWD を渡さないと、表示される解決後のパスが期待と食い違った
- macOS では一時ディレクトリが `/var` 配下にあり、`/var` がシンボリックリンクのため、期待は `/var/...`、実際は `/private/var/...` になった
- 独立検証でも同じ食い違いが 1 回出て、検証の側の PWD の指定を直して誤検出を除いた

## 原因

- bash は起動時に、受け継いだ環境変数 PWD が実際の作業ディレクトリを指していれば、その字面を `$PWD` に使う。環境変数 PWD が無い・食い違うときは、物理パスを求め直す
- テストの起動の仕組み(Node.js の子プロセスの起動で作業ディレクトリだけを指定する方法など)は、環境変数 PWD を自動では合わせない
- Linux の一時ディレクトリ(`/tmp`)はシンボリックリンクを含まないことが多く、macOS でだけ現れる

## 回避方法

- 作業ディレクトリを指定して起動する step・テストの補助関数は、環境変数 PWD も同じ値にして渡す
- 論理パスと物理パスの違いを確かめるテストは、シンボリックリンクを自分で作って行う。環境の一時ディレクトリの構成に頼らない
- 環境変数 PWD が無い・食い違うときの挙動(bash が求め直した物理パスになる)は、別のテストで固定する

## 次回の対応

- 実行時の読み手(ジョブを起動するコマンドなど。別の UC)のテストでも、同じ補助関数を使う
- ジョブスケジューラから起動されるときは、環境変数 PWD が渡らないことがある。設定ファイルを絶対パスで指定すれば作業ディレクトリは使われないことを、利用者向けの手引きに書く候補とする
