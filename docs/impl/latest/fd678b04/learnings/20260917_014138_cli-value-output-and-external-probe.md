# bash CLI の値出力は printf 固定書式、外部プロセス問い合わせは待機上限つきにする

## 何が起きたか

attempt-1 の独立検証で blocker が 3 件出た。

- 設定ファイル由来の値を `echo` で出力していたため、値が `-n` / `-e` / `-ne` のとき stdout の行が欠ける・変形する(F-001)
- `key=value` / `key: value` の切替が呼び出し側ごとに書かれ、出力書式の共通関数が無かった(F-002)
- runner `--help` の問い合わせに待機上限が無く、終了しない runner で CLI が復帰しなかった(F-028)

## 原因

- bash の `echo` は先頭引数をオプションとして解釈する。利用者が書いた値をそのまま渡すと出力契約が壊れる
- 出力フォーマット規約(ui-design.md)が「値に空白を含む場合は `key: value`」「パス系は常に `key: value`」と 2 種類の規則を持つのに、規則を 1 箇所に閉じ込めていなかった
- 外部プロセスの起動を gateway 層に置いたが、「応答しない」を出力の有無でしか判定しておらず、時間の上限を設けていなかった

## 回避方法

- 値の出力は全層で `printf '%s=%s\n'` / `printf '%s: %s\n'` の固定書式にし、`echo` を使わない。`-n` / `-e` / `-ne` / 空文字 / タブを境界テストに入れる
- 出力書式は domain 層の共通関数(`cli_field_line` / `cli_path_field_line`)に閉じ込め、キー順序は usecase の描画関数で 1 箇所に固定する
- 外部プロセスは独自プロセスグループで起動し、待機上限到達時に TERM → KILL で停止して「未応答」に写像する。終了しない実体(`exec sleep 60`)を実ファイルで用意した gateway / CLI テストを置く
- 一時ファイルの作成失敗など「検証側の障害」は runner 未応答と区別し、CLI 共通の実行エラー(終了コード 6)で返す(attempt-2 で major F-001 として残った。次 attempt で対応)

## 次回の対応

- bash tier の実装開始時に、`grep -n 'echo' src/` が利用者由来の値を含む行を 0 件にするチェックを TDD の最初に置く
- gateway 層で外部プロセスを起動する関数は、待機上限・停止手順・準備失敗時の終了コードをシグネチャの一部として最初から設計する
