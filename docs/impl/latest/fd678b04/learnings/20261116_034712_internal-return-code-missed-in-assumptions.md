# 層の間だけで使う戻り値の選択が、前提の記録から漏れた

## 何が起きたか

- 独立検証が、前提の記録 25 件に無い判断を 1 件見つけた
- 内容: 入力の複製に失敗したとき、読み込みの関数は内部の戻り値 7 を返し、上の層がコマンドの終了コード 6 へ変える
- コマンドの終了コード 6 と error・hint の行は仕様どおりで、機能の欠陥ではない(軽微な指摘 1 件)
- この判断は以前の回からコードにあり、今回の変更で足したものではない

## 原因

- 前提を洗い出すとき、「利用者に見える挙動」を中心に候補を挙げた。層の間だけで使う値は候補に入らなかった
- 仕様はコマンドの終了コードだけを定める。関数の戻り値は仕様の対象ではないため、「仕様に無いことを決めた」という意識が生まれにくい
- 再実行のたびに前回の記録を引き継ぐため、最初に漏れた判断は漏れたまま残る

## 回避方法

- 前提の洗い出しで、仕様の終了コードと違う値を関数が返す箇所を検索する(`return` に続く数値のうち、仕様の終了コードの表に無い値)
- 見つけた値は、「どの層がコマンドの終了コードへ変えるか」と一緒に前提へ書く
- 利用者に現れない内部の値は、仕様への要求にはしない。記録にだけ残す

## 次回の対応

- この機能の前提の記録を次に更新するとき、内部の戻り値 7 の前提を足す
- 残りの機能の実装でも、層の間の戻り値の表を実装の段の完了記録に書く
