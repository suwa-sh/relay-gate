# コンテナの共有マウント上では、実行権限の判定が変わりテストが失敗する

## 何が起きたか

- 独立検証が Linux のコンテナで全テストを実行したとき、481 件のうち 1 件(runner が実行可能でない場合の確認)が失敗した
- 契約から作った期待値との照合でも、実行可能でないはずのファイルへ問い合わせが行われ、warn 行の差が出た
- 一時ディレクトリをコンテナ内に作り直すと、481 件と照合 324 通りがすべて通った。実装の欠陥ではなかった

## 原因

- テストの一時ディレクトリ(環境変数 `TMPDIR`)を、ホストと共有するマウント上に置いていた
- 共有マウント上では、実行権限を外した(`chmod 644`)直後のファイルでも、実行可能かどうかの判定(`test -x`)が「実行可能」を返した。同じコンテナの `/tmp` では「実行可能でない」を返した

## 回避方法

- コンテナでテストを実行するときは、一時ディレクトリをコンテナ内のファイルシステムに作る(コンテナの中で `mktemp -d` を実行し、その結果を `TMPDIR` にする)
- リポジトリの複製は共有マウントで渡してよいが、テストが権限を変えるファイルは共有マウントに置かない
- 権限の判定に関わるテストが 1 件だけ失敗したときは、実装を疑う前に、同じファイル操作を共有マウントとコンテナ内の両方で試して比べる

## 次回の対応

- ほかの UC の再実行でも、Linux の確認はコンテナ内の一時ディレクトリで行う
- 開発規約への書き足しの提案は `20261115_145719_proposal-context.md` に書いた
