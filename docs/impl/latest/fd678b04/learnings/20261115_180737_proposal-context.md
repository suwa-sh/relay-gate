# 提案: プロジェクトの CLAUDE.md / dev-rules に書き足す内容

この提案は既存の CLAUDE.md と `docs/dev-rules/` を変更しない。採否は利用者が決める。`20261115_145719_proposal-context.md` の提案に足すもので、置き換えではない。

## 背景

- 仕様の生成時に足された、方針資料に無い規則(4 キーの絶対パス必須)が、方針資料の設定例と食い違っていた(詳細: `20261115_180737_spec-rule-absent-from-policy-docs.md`)
- 作業ディレクトリを基準にするパスのテストで、環境変数 PWD を渡さないと字面が食い違った(詳細: `20261115_180737_logical-pwd-in-path-tests.md`)
- テストの段を同時に走らせると、関係の無い場面が 1 回だけ落ちた(詳細: `20261115_180737_concurrent-test-runs-snapshot-failure.md`)

## 提案内容

| 対象 | 書き足す内容(案) |
|---|---|
| CLAUDE.md の「方針の正本」 | 仕様の生成時に足された、方針資料に無い規則は、理由の記録が無ければ方針資料へ戻す対象として早めに洗い出す。UC の実装を始める前に、その UC が読む設定ファイルとコマンドの規則について一覧を作る |
| CLAUDE.md の「方針の正本」 | 方針資料の設定例・コマンド例は、字面のまま入力にした BDD の場面を持つ |
| `docs/dev-rules/test-strategy.md` | 作業ディレクトリを指定してコマンドを起動するテストは、環境変数 PWD も同じ値にして渡す。論理パスと物理パスの違いは、テストが自分で作ったシンボリックリンクで確かめる |
| `docs/dev-rules/test-strategy.md` | テストの段(単体テスト、tier の BDD、UC の BDD、受け入れ)は 1 つずつ順に実行する |
| `docs/dev-rules/coding-rules.md` | 設定の値からパスを決める処理は、domain の関数に置き、検証コマンドと実行時の読み手が同じ関数を使う。読み込みは設定に書いた値のまま載せる |

## 期待する効果

- 残りの UC で、仕様が方針資料から離れた箇所を実装の前に見つける
- macOS と Linux でテストの結果が食い違う原因を減らす
- 検証コマンドと実行時の読み手で、同じ設定から同じ実体が選ばれる状態を保つ
