# 提案: プロジェクトの CLAUDE.md / dev-rules に書き足す内容

この提案は既存の CLAUDE.md と `docs/dev-rules/` を変更しない。採否は利用者が決める。

## 背景

- 性能の値の位置づけ(目標値か合否の条件か)が文脈に無く、実装と独立検証が合否の条件として扱った
- bash で数 MB の文字列を扱うときの遅い形が、検証種別ごとに繰り返し現れた(詳細: `20261115_093126_bash-large-string-processing-patterns.md`)

## 提案内容

| 対象 | 書き足す内容(案) |
|---|---|
| CLAUDE.md の「実装規約」 | 設定ファイルの検査の性能(5,000 行以内かつ 8 MB 以内を 10 秒以内)は目標値である。入力を制限しない。超えても検証の結果は変わらない。合否の検査にしない(2026-11-13 / 2026-11-15 の利用者の決定)。目標との差は記録して進む |
| `docs/dev-rules/coding-rules.md` | 大きな入力を扱う bash の書き方: (1) 表示する値はまとめて外部コマンドへ渡す、(2) 行の構造の取り出しは sed 1 回で行う、(3) 大きな文字列を配列・サブシェルで写さない、(4) sed は基本正規表現と生のバイトで書き `LC_ALL=C` で実行する |
| `docs/dev-rules/test-strategy.md` | 性能の測定は Linux と macOS、ロケール C と C.UTF-8 の 4 通りで行う。性能のテストは合否の線ではなく、極端な悪化を検出する入力に絞る |

## 期待する効果

- 残りの検証種別(速報クロスチェック設定・slot ジョブマップ・確報クロスチェック設定)の再実行で、同じ確認と作り直しを繰り返さない
