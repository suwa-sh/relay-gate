# スキル改善提案(既存 SKILL.md は編集しない。提案のみ)

## 提案 1: 共有仕様参照集合に「自 UC が定義するコマンドを使う UC の tier md」を含める

- 対象: distillery-impl の UC 初期化(shared_spec_refs の決定)
- 事象: CLI 契約で `defined_in_uc` が自 UC、`used_by_ucs` が他 UC のコマンドについて、他 UC の tier md が「〜の契約に以下を追加する」形で細則(待機上限 5 秒)を持っていた。実装者・検証者ともその tier md を読まず、spec_absent と判定した
- 提案: UC 初期化で CLI 契約(または API 契約)を走査し、自 UC が `defined_in_uc` のコマンドについて `used_by_ucs` の各 UC の tier md を shared_spec_refs に自動追加する。追加理由(どのコマンドの used_by か)を done に記録する
- 期待効果: 「仕様に無い」誤判定と、仕様側にある値との不一致(4 秒 vs 5 秒)を防ぐ

## 提案 2: spec_absent 判定の前に仕様全体の横断検索を必須にする

- 対象: 実装者の AssumptionRecord 抽出、検証者の assumption_verdicts
- 事象: 上記と同じ。自 UC の spec と cross-cutting だけを照合先にしていた
- 提案: AssumptionRecord に `searched:`(検索語と検索範囲)を任意フィールドとして追加し、検証者は同じ検索を再実行して `spec_absent` を確定する。検索範囲は specs_root 全体を既定にする
- 期待効果: 検証者が blind join で前提を照合する際、照合先の網羅性が判定に含まれる

## 提案 3: UC 横断 Scenario の issue から feedback CR を自動起票する

- 対象: テスト足場作成時の cross_uc_scenarios issue と、feedback draft の作成
- 事象: テスト足場作成時の issue に「Then の責務分離を feedback で要求する」提案が書かれ、統合テストでは暫定注入で通した。feedback 作成時に issue と injections を突き合わせて CR を手で起こした
- 提案: issue の `kind: cross_uc_scenarios` と done の `injections[].kind: provisional_harness` を feedback 作成の必須入力にし、Scenario 名・担当 UC・暫定注入の有無を CR の「観測した事実」に定型で埋める
- 期待効果: 暫定注入で pass した Scenario が、要件の証跡として誤読される前に仕様へ戻る

## 提案 4: 検証側障害と外部未応答の区別を verify の観点に明記する

- 対象: dist-impl-verify の operability / fault_tolerance 観点
- 事象: attempt-2 の major F-001(一時ファイル作成失敗が runner 未応答に化ける)は、故障注入で初めて見つかった
- 提案: 観点の確認項目に「外部プロセス・外部ファイルの問い合わせで、準備段階の失敗(mktemp / mkdir / 権限)が外部側の失敗と同じ出力に写像されていないか」を追加する
- 期待効果: bash tier に共通する縮退の誤報を定型で検出できる
