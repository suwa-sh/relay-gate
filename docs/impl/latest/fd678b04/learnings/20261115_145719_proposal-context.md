# 提案: プロジェクトの CLAUDE.md / dev-rules に書き足す内容

この提案は既存の CLAUDE.md と `docs/dev-rules/` を変更しない。採否は利用者が決める。`20261115_093126_proposal-context.md` の提案に足すもので、置き換えではない。

## 背景

- 設定ファイルの値を読み取りの途中だけ作業用の変数に置く読み方が、仕様に定めの無い安全上の前提として指摘された(詳細: `20261115_145719_prohibition-rule-needs-transient-boundary.md`)
- コンテナの共有マウント上に一時ディレクトリを置くと、実行権限の判定が変わりテストが失敗した(詳細: `20261115_145719_container-bind-mount-execute-permission.md`)

## 提案内容

| 対象 | 書き足す内容(案) | 条件 |
|---|---|---|
| `docs/dev-rules/coding-rules.md` | 設定ファイルの行を受ける作業用の変数は、環境変数にしない。読み終えたとき・失敗したときに空にする。読み取りの後まで残すのは、その読み手が使うキーの値とキー名だけにする | 利用者が最終確認で「一時的な保持を許す」を選び、仕様に反映された後 |
| `docs/dev-rules/test-strategy.md` | コンテナでテストを実行するときは、一時ディレクトリをコンテナ内のファイルシステムに作る(共有マウント上では実行権限の判定が変わる) | なし |
| CLAUDE.md の「開発プロセス」 | 現行の実装を仕様に書く変更要求では、実装の値の流れと規則の文面を突き合わせてから出す。禁止の形の規則は、対象の領域・期間・後に残してよいものまで書く | なし |

## 期待する効果

- 残りの読み手(ジョブを起動するコマンドなど)の実装で、同じ境界の判断を繰り返さない
- Linux の確認で、環境が原因の失敗を実装の欠陥と取り違えない
