## 提案 6: bootstrap が生成する CI の ATDD ゲートは、完了済み UC の Scenario だけを選択実行する

- 対象: bootstrap の CI 生成(P6)と、CI ゲートの設計を記す dev-rules(test-strategy.md)
- 事象: P6 が生成した `atdd` ジョブは `features/atdd/` を全件 strict 実行する。P7 は全 SPEC の Scenario(本リポでは 50 feature / 122 Scenario)を生成済みだが、step 定義は UC の完了(S7)ごとに 1 UC 分ずつ増える。最初の UC の PR で 121 件が undefined になり `atdd` ジョブが fail した(他の 11 ジョブは pass)。S7 はタグ完全一致で当該 UC の Scenario だけを実行するため、ローカル green と CI red が食い違った
- 対処(本リポで実施): `scripts/ci/atdd-tag-expression.js` が uc-map の `atdd_scenarios` と各 UC の `status.yaml`(`state: completed`)から `--tags` 式を組み立て、CI はその式で選択実行する。完了 UC が無ければスキップ
- 提案:
  - P6 の CI テンプレートで `atdd` ジョブを「完了済み UC の Scenario をタグ完全一致で選択実行」にする(選択スクリプトもテンプレートとして配布する。yaml パーサの依存を P3 の devDependency に含める)
  - dev-rules の test-strategy.md「実行ゲート」表に、CI の atdd ゲートは全件実行ではなく完了済み UC の選択実行であることを明記する(ローカル green = CI green の原則を ATDD にも成立させる)
  - 将来的に全 UC が完了したら全件実行と同値になるため、選択方式のまま運用してよい
- 期待効果: 最初の UC から PR の CI が green になり、undefined を「未着手」と「実装漏れ」で区別できる
