# 検証・実装 skill への提案(環境前提 probe と責務境界チェック)

## 何が起きたか

- 独立検証がサンドボックスの制約(loopback socket / shared memory 禁止)で実 DB テストを開始できず、実装と無関係に TDD gate が赤になった
- E2E Scenario に後続 UC の責務が含まれており、UC BDD でハーネス注入が必要になった
- 契約の未定義(hash 正規化、時刻精度、引数保存形式)を実装が仮置きで埋め、独立検証の後で feedback に回った

## 原因

verifier skill に検証環境の前提確認が無く、implementer / test-scaffold skill に「Scenario の Then ごとの責務 UC」と「契約の未定義項目の早期抽出」の定型チェックが無い。

## 回避方法

- verify skill: gate 再実行の前に、テストが要求する環境機能(TCP loopback、shm、docker、必要バイナリ)を probe し、不足時は `environment_failures` として分離して blocker に数えない。再検証は環境を変えて行う旨を出力する
- test-scaffold skill: E2E Scenario の Then ごとに担当 UC を判定し、他 UC の責務を含む Scenario を「UC 横断」として一覧化して issue に出す(ハーネス注入の要否を着手前に決める)
- tier-impl skill: 仕様読込時に「複数 UC が共有する値の算出規則(hash、時刻精度、シリアライズ形式、識別子形式)」を未定義リストとして抽出し、仮置きする場合は as-built と issue に同時記録する

## 追記(オーケストレータ視点、2026-08-22)

### 何が起きたか(追加 5 件)

1. verifier_model が Claude 以外(Codex gpt-5.6-sol)のとき、Agent ツールでは起動できず `codex exec` で起動した。
   サンドボックス(`-s workspace-write`)は loopback socket / shared memory を禁止し、実 PostgreSQL テストが開始できず
   偽 blocker になった。さらに Bash ツールの 600 秒上限で `codex exec` が kill された
2. 仕様還流が UC の feature branch 上で起きたため、S0 再実行の `impl(bootstrap)` commit が UC branch に混在した。
   SKILL の「S0 は base branch へ merge 後に再実行」は、還流成果物が feature branch にしか無い状況では実行不能
3. bootstrap P3 はプラグイン同梱の dev-rules をコピーするため、リポ側でローカル改訂した `test-strategy.md`
   (uc_slug 命名規約)を上書きしうる(今回はプロンプト指示で回避)
4. bootstrap P7 が `features/atdd/*.feature` を再生成すると、S7 が付けた `@uc_{uc_id}` タグが消える
5. event_id を `date` でなく論理時刻(順序制約を守るため実時計より先行)で刻んだ。state-schema は
   `date +%Y%m%d_%H%M%S` 取得を規定しているが、同一秒・順序逆転時の扱いが未定義

### 回避方法(提案)

- dist-impl-run S5 dispatch: verifier_model が Agent ツールで指定不能なモデルの場合の起動手順を定義する
  (`codex exec -m <model> -C <repo> -o <last-message> - < <prompt-file>`、実体テストを含む tier は
  `--dangerously-bypass-approvals-and-sandbox`、`nohup` + marker 待ちでツールタイムアウトを回避、
  完了後に `git status` で write-set 逸脱を検査)。環境制限で開始不能だったテストは
  `stage_invalidated(reason: verification_environment_limited)` で退避し同一 attempt で再検証する
- dist-impl-run 起動シーケンス 2: 「還流中の UC(blocked_on_spec から再開)では feature branch 上で
  `impl(bootstrap)` commit を許し、最終 squash に含める」例外を明文化する
- dist-impl-bootstrap P3: dev-rules はリポ側を正とし、差分は報告のみ(上書きしない)。初回生成時のみコピー
- dist-impl-bootstrap P7: 再生成時に既存 feature の `@uc_*` タグを Scenario 名キーで引き継ぐ
- state-schema: event_id は単調増加を必須とし、実時計が先行 event より前なら「先行 event + 1 秒」の論理時刻を
  許容する(replay は event_id 昇順のため)。created_at は実時計でよい
