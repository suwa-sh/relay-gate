# bash で設定ファイルを読むときの落とし穴(read / プロセス置換 / 文字列操作 / 配列スライス)

## 何が起きたか

独立検証で、bash の言語仕様に起因する欠陥が順に見つかった。

| 構文 | 起きたこと | 見つかった回 |
|---|---|---|
| `read -r` | NUL バイトを黙って落とす。`J<NUL>2` が `J2` になり、検証を通過した | attempt 2 |
| `read -r` | 改行の無い最終行で失敗を返す。読み飛ばすと最終行の違反を見逃す | attempt 3 の自己点検 |
| プロセス置換 `< <(cmd)` | `cmd` の失敗が親へ伝わらない。`sort` や `tr` が失敗しても、重複なし・異常行なしとして成功した | attempt 3 |
| 同じパスを 2 回開く | 事前点検と読み込みの間に `mv` で差し替わると、どちらのファイルにも無い行を受理した | attempt 4 |
| 1 文字ずつの `${s:i:1}` | 文字列長の 2 乗の時間になる。10 万文字の行で約 100 秒かかった | attempt 2〜3 |
| 配列スライス `${a[@]:i}` を繰り返す | 行数の 2 乗の時間になる | attempt 1〜2 |
| ロケール依存の正規表現 | 文字クラスがロケールで変わる | attempt 3 の自己点検 |

## 原因

- bash の文字列は NUL を保持できない。
- プロセス置換の終了状態は、`$?` にも `pipefail` にも反映されない。
- bash の部分文字列と配列スライスは、先頭からの走査で位置を求める。
- ファイルのパスは、開くたびに別の実体を指し得る。

## 回避方法

- NUL の検出は、bash に取り込む前に外部コマンド(`tr` など、`LC_ALL=C`)で行う。
- 最終行は `while IFS= read -r line || [[ -n $line ]]` の形で読む。
- 補助コマンドの結果は、一時ファイルへ書いて終了状態を確認してから読む。
  - 終了状態 0 でも、出力の欠落を検査する(行数、完了を示す行)。
- 入力は最初に一時コピーへ 1 回だけ複製し、すべての検査でそのコピーを使う。
- 長い文字列は、区切り文字までをまとめて取り込む(パターン展開や固定幅の窓)。
- 配列は添字で直接参照し、スライスを繰り返さない。
- 正規表現と文字クラスは `LC_ALL=C` で評価する。

## 次回の対応

- 設定ファイルを読む tier の実装前チェックリストに、上表の 7 項目を入れる。
- 各項目に、実ファイルを使う bats の再発防止テストを用意する(NUL、改行なしの最終行、補助コマンドの失敗注入、差し替え、長い行)。
