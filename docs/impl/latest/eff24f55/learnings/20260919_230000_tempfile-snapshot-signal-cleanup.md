# bash で入力を一時ファイルへ複製するときの後始末(作成直後のシグナル、trap の戻し方)

## 何が起きたか

attempt 5 で、検証中の差し替え(attempt 4 の F-001)を単一スナップショットで直した。
入力を一時ファイルへ 1 回だけ複製し、点検と解析は複製だけを読む方式である。
差し替えの問題は解消した。一方で、一時ファイルの後始末に次の穴が残った。

| 状況 | 起きたこと | 検出 |
|---|---|---|
| `mktemp` の直後、変数への代入の前に HUP / INT / TERM を受けた | 0 バイト・0600 の一時ファイルが残った | 独立検証 F-101(minor) |
| サブシェルやコマンド置換の中で `trap -p` を読んだ | 実際には効いていない親の trap が表示された | 実装者の自己点検(bash 5.3) |
| 一時ファイルの置き場所に書き込めない | 正しいジョブマップでも終了コード 6 になった | 外部レビュー(仕様の判断として記録) |
| 読み込み中に外部の処理が複製を消した | リダイレクトのエラーに一時パスが出た(終了コード 6) | 外部レビュー(閾値未満) |

## 原因

- `path=$(mktemp ...)` は、一時ファイルの作成と、削除対象としての登録が分かれている。
  - 間にシグナルが届くと、trap は削除対象のパスを知らない。
- bash はサブシェルの中で、親の trap を `trap -p` に表示することがある。
  - 表示どおりに EXIT の trap を戻すと、サブシェルの終了時に親の終了処理が動く。
- 単一スナップショットは、一時ファイルの置き場所という新しい環境依存を持ち込む。

## 回避方法

- 一時ファイルを作る前に、削除用の trap を登録しておく。
  - 例: 一時ディレクトリを先に作って登録し、その中にファイルを作る。
  - 例: trap の中で、命名規則(`relay-gate-job-map.*`)と自プロセスの識別子で残骸を探す。
- trap は読み込みの間だけ登録し、終了後に呼び出し元の trap へ戻す。
  - EXIT の trap は差し替えない。戻る経路ごとに削除する。
- 一時ファイルのパスを、利用者向けの出力に出さない。
  - リダイレクトの失敗は、`2>/dev/null` などで一時パスを抑止し、固定の error 行で報告する。
- 一時ファイルの置き場所・権限・削除時期を、前提として記録し、仕様の確定を求める。

## 次回の対応

- 一時ファイルを使う bash の処理には、次の bats テストを用意する。
  - 作成直後のシグナル注入(`mktemp` を関数で包み、直後に `kill -TERM $$`)で残骸が 0 件であること。
  - 呼び出し元の EXIT / INT / TERM / HUP の trap が元に戻ること。
  - TMPDIR に書き込めない環境で、決めた終了コードと error 行になること。
- 設定ファイルを読む他の機能でも、単一スナップショットを採るなら同じ後始末の部品を共有する。
