# 事前のバイト点検と CSV 読み込みの間にファイルが差し替わると、不正な行を受理する

- 起票: オーケストレータ(4 回目の独立検証の blocker。ユーザーの取り決めにより実装へ差し戻さない)
- 種別: 未解決の実装上の指摘 + 仕様の不足(spec-gap)
- 対象: `facade/src/repository/job_map_repo.sh:188`(`validate-config.sh --job-map`)
- 出典: `docs/impl/latest/eff24f55/stages/attempt-4/S5_verify.tier-facade.findings.yaml` の F-001

## 事実

- 実装は、NUL・不正 UTF-8 の事前点検(tr / sed)と、CSV の読み込みで、同じパスを別々に開く
- 点検の直後に、同じ行数の別ファイルへ `mv` で置き換えると、NUL を含む `J<NUL>2` の行が `J2` として受理される(終了コード 0、rows=1)
- 置き換え後のファイルを単独で検証すると、正しく終了コード 2(`csv quote is invalid line=2`)になる
- 検証側は `tr` の直後に `mv` を実行する関数を注入して、差し替えのタイミングだけを制御して立証した
- CLI 契約の設定ファイル編集規則(一時ファイルを書いて `mv` で置換)は、検証中の差し替えが起こり得る運用を指定している

## 現在の扱い

- 4 回目の検証で出た「異常な入力・異常な環境」の同種の新規指摘のため、ユーザーの取り決め(2026-09-19)に従い、実装へ差し戻さずに残す
- 通常の運用(検証中にファイルを置き換えない)では発生しない

## 修正案(実装側)

- 検証の最初にファイルを 1 回だけ読み、事前点検と CSV 解析が同じ不変の入力(同一の一時コピーまたは同一の読み込み結果)を参照する

## 要求の候補(仕様側)

- 設定ファイルの検証が「検証中の差し替え」に対して何を保証するか(単一スナップショットの検証)を設定契約または CLI 契約に明記する
- `20260919_195500_malformed-input-policy-undefined.md` の「入力の守備範囲」に、異常な環境(検証中の差し替え、補助コマンドの故障)をどこまで対象にするかを含める
