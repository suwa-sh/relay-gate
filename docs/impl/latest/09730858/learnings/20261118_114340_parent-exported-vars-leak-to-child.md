# 親の環境にある同名の変数は、代入しただけで子へ渡ってしまう

## 何が起きたか

- 仕様は「接続の参照名(`RAPID_DB_CONN_REF`)と配置ディレクトリ(`RELAY_GATE_HOME`)を runner へ渡さない」と定める。
- 1 回目の実装は、渡す環境変数を明示して設定していた。渡さない変数を外す一覧に、接続の参照名が入っていなかった。
- 独立した検証の 1 回目で、次の指摘を受けた(重大)。
  - facade を起動する側の環境に `RAPID_DB_CONN_REF` があると、その値が runner に渡る。

## 原因

- bash では、親から受け取った変数は「子へ渡す」印(export 属性)が付いたままである。
- 設定ファイルから読んだ値を同じ名前の変数へ代入しても(`printf -v` を含む)、印は消えない。代入した値が、そのまま子へ渡る。
- 「渡すものを設定する」だけでは足りない。「渡さないものを外す」処理が要る。

## 回避方法

- 子を起動する直前に、渡さないと決まっている変数を明示して外す(`unset`、または `env -u`)。
- 外す対象は、次の 3 種類である。
  - 仕様が「渡さない」と名指しする変数
  - 設定ファイルにしか要らないキー(同じ名前の変数へ読み込むもの)
  - 相手 slot のキー
- 環境を空にする方式(`env -i`)は採らなかった。`PATH` や DB クライアントの設定まで消え、runner が動かなくなるためである。
- テストは、親の環境に同じ名前の変数を置いた状態で起動し、子が記録した環境に無いことを確かめる。

## 次回の対応

- 「〜を渡さない」という仕様の文は、「親の環境にあっても渡らない」ことまでテストにする。
- 設定ファイルのキーを増やしたら、外す対象の一覧(`facade/src/usecase/launch_slots.sh`)も合わせて見直す。
