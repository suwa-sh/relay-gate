# CLAUDE.md / dev-rules への提案(relay-gate)

既存の CLAUDE.md と `docs/dev-rules/` は変更していない。取り込むかどうかは保守者が判断する。

## 提案 1: 管理 DB へのつなぎ方を、利用者の承認の後に 1 か所へ書く

- 現状: 「管理 DB のクライアントは `psql`。接続の参照名を接続サービス名として渡す」は、この機能の前提の記録と作業の指示にだけ書かれている。
- 問題: 管理 DB を使う後続の機能(速報クロスチェック、ハングの検知、確報クロスチェック、ハウスキープ)の実装者が、同じ点をもう一度決めることになる。
- 提案: 最後の確認で利用者が承認したら、CLAUDE.md の「プロジェクト固有」に次の 1 行を足す。
  - 管理 DB のクライアントは `psql`。接続の参照名(`*_DB_CONN_REF` の値)を接続サービス名として渡す。接続先はクライアント側の接続設定が決める。SQL に入れる値は `psql` の変数で渡す。`psql` のエラー出力は、実行ログと標準エラーに出さない。
- 補足: 仕様(CLI の契約)にコマンド名を書くかどうかは、利用者の判断による。この提案は、仕様を変えずに実装の決まりとして残す案である。

## 提案 2: 子プロセスの起動の決まりを `docs/dev-rules/coding-rules.md` に書く

- 提案: 次の 3 行を足す。
  - 子プロセスの起動の成否は、「開始の合図 → 成否」の 2 段で受け取る。「何も届かなければ成功」で判定しない(`facade/src/gateway/runner_process_adapter.sh` の方式を再利用する)。
  - 子へ渡さないと決まっている変数は、起動の直前に明示して外す。親の環境に同じ名前の変数がある場合をテストする。
  - 子の標準入力・標準出力・標準エラーは、呼び出し側のものを継承させない(background の子が、ジョブスケジューラの出力先を開いたままにしないため)。
- 根拠:
  - `learnings/20261118_114340_bash-exec-failure-needs-start-signal-handshake.md`
  - `learnings/20261118_114340_parent-exported-vars-leak-to-child.md`

## 提案 3: 一時 PostgreSQL の補助の置き場と使い方を `docs/dev-rules/test-strategy.md` に書く

- 現状: 一時 PostgreSQL の補助は `facade/features/steps/support/temp-postgres.js` にある。結合テストと受け入れテストは、これを読み込んで使う(複製なし)。テーブルは、契約の生成物から組み立てる暫定の定義である。
- 問題: 管理 DB を使う後続の機能(別のディレクトリ)が、同じ補助をもう一度作るおそれがある。
- 提案: 次の規則を足す。
  - 一時 PostgreSQL の補助は 1 つだけ持ち、ほかのテストは読み込んで使う。
  - 接続の参照名は、一時的な接続設定ファイル(環境変数 `PGSERVICEFILE`)で一時インスタンスに結び付ける。
  - 正式なテーブル定義(マイグレーション)ができたら、暫定の定義を置き換える。

## 提案 4: 順を確かめるテストの決まりを `docs/dev-rules/test-strategy.md` に書く

- 提案: 次の 1 行を足す。
  - 仕様が順を定める処理のテストは、別々のプロセスが書いた記録の並びだけで判定しない。順を入れ替えた一時的な複製で落ちることを確かめる。
- 根拠: `learnings/20261118_114340_order-assertion-needs-sync-and-mutation-check.md`

## 提案 5: Linux の再現環境に Node.js と PostgreSQL を入れる

- 現状: 手元の Linux のコンテナ(`relay-gate-ci:ubuntu24`)には、Node.js と PostgreSQL が無い。機能のシナリオ・結合テスト・受け入れテストは、macOS でだけ実測した。
- 問題: この機能は、macOS と Linux で挙動が違う部分(`setsid` の有無、bash の版による exec の挙動)を持つ。Linux で確かめたのは単体テストだけである。
- 提案: 再現用のイメージに Node.js と PostgreSQL を足す(先行の機能の提案に、PostgreSQL を加えたもの)。
