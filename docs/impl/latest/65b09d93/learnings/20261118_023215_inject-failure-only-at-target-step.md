# 途中の処理だけを失敗させたいときは、手前の処理を通す形で失敗を起こす

## 何が起きたか

- scenario「`--help` 問い合わせの準備に失敗すると終了コード 6 で止まる」の前提は、「一時ファイルの作成先(`TMPDIR`)が存在しないディレクトリを指す」である。
- この前提のままだと、問い合わせより手前の「設定ファイルの複製」が先に失敗した。
- 出力は別のエラー(`config snapshot failed`)になり、scenario が期待する行に届かなかった。

## 原因

- 検証コマンドは、同じ `TMPDIR` を 2 つの処理(設定ファイルの複製、問い合わせの応答の受け取り)で使う。
- 環境変数のような「全体に効く条件」で失敗を起こすと、最初にその条件を使う処理で止まる。

## 回避方法

- 前提の文面どおり `TMPDIR` を存在しないディレクトリにする。
- そのうえで、PATH の先頭に代わりの `mktemp` を置く。
  - 設定ファイルの複製(テンプレートの末尾が `.part`)だけを、書けるディレクトリへ向けて本物の `mktemp` に渡す。
  - それ以外は、`TMPDIR` のまま本物の `mktemp` に渡す。問い合わせの一時ファイルの作成は、実際に失敗する。
- 検証コマンドの振る舞いは変えない。
- step: `facade/features/steps/assign-slot-runner-scripts.steps.js`
- 記録: `docs/impl/latest/65b09d93/issues/20261118_013500_probe-preparation-failure-scenario-unreachable.md`

## 次回の対応

- 失敗を起こす scenario の step を書く前に、同じ条件を手前で使う処理が無いかを、実際に 1 回実行して確かめる。
- 手前で止まる場合は、対象の処理だけが失敗する形に step を組む。scenario の文面の直しは、実害が無ければ要求にしない。
