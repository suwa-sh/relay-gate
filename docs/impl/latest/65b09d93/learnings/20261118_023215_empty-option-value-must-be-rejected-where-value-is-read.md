# 値を取るオプションの空の値は、値を読む場所でまとめて拒否する

## 何が起きたか

- 標準の runner の引数の検査が、`--execution-spec ""`(空の値)を受理した。
- 終了コードは、引数不正の 2 ではなく、仮置きの 6 になった。
- 1 回目の独立検証が blocker として指摘した。2 回目の実装で直した。

## 原因

- 空の値の検査を、オプションごとに別の場所へ書いていた。
  - `--run-id` / `--job-id` は、最後の「空でないこと」の検査で拒否していた。
  - `--role` / `--mode` は、列挙の検査で拒否していた。
  - `--execution-spec` は任意のオプションで、どちらの検査も通らなかった。
- 単体テストは「値の欠落」を確かめていたが、「空の値」を確かめていなかった。

## 回避方法

- 値を取るオプションは、値を受け取る分岐 1 か所で「値が無い」と「値が空」を同じ引数不正として拒否する。
- 単体テストは、値を取るオプションのすべてに空文字を 1 つずつ渡す形で書く(今回は 5 オプション × 区切りの `--` の有無)。
- 実装: `facade/src/presentation/standard_runner.sh`、テスト: `facade/test/presentation/standard_runner.bats`

## 次回の対応

- 後続の機能で CLI のオプションを足すときは、任意のオプションにも空の値のテストを書く。
- 前提の記録に「後の値で上書きしたあとに検査する」のような検査の順序を書くときは、実装の実際の順序と照らしてから書く(今回は記録のほうが不正確だった)。
