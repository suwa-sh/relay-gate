# CLAUDE.md / dev-rules への提案(relay-gate)

既存の CLAUDE.md と `docs/dev-rules/` は変更していない。取り込むかどうかは保守者が判断する。

## 提案 1: 仕様への要求の基準を CLAUDE.md に書く

- 現状: 「仕様への要求は、出さないと実装や運用で実害が出るものだけにする」という利用者の方針(2026-11-18)は、作業の指示と完了の記録にだけ書かれている。
- 問題: 実装者と検証者は方針を知らないまま、issue に「仕様へ要求を出す」と提案する。
- 提案: CLAUDE.md の「開発プロセス」に、次の 2 行を足す。
  - 仕様への要求は、出さないと実装や運用で実害が出るものだけにする。scenario の文面の直しや、作為的な入力の扱いは要求にしない。
  - 仕様を変えると全工程の再確認が要る。実装の効率が下がる要求は取り下げてよい。

## 提案 2: 後続の機能のコマンドを起動する scenario の扱いを `docs/dev-rules/test-strategy.md` に書く

- 現状: 機能をまたぐ scenario の扱いは、機能ごとの issue にだけ書かれている(3 つの機能で同じ記録を繰り返した)。
- 提案: 次の規則を足す。
  - 担当外のコマンドが無い間、該当の step は skipped を返す。コマンドができたのに step が未実装なら、失敗させる。
  - 代役のコマンドは作らない。
  - 担当の機能を実装するときに、保留元の feature も合わせて流す。

## 提案 3: Linux の再現環境に node を入れる

- 現状: Linux のコンテナ(`relay-gate-ci:ubuntu24`)には node が無い。tier の BDD は macOS でだけ実測した。単体テストと lint は Linux でも実測した。
- 問題: macOS で通り、Linux で落ちる失敗を、BDD では手元で見つけられない(先行機能で、単体テストについて同じ種類の失敗が 3 パターン起きた)。
- 提案: 再現用のイメージに node を足す。足すまでは、「BDD は Linux で実測していない」ことを完了の記録に書き続ける。

## 提案 4: CLI の引数の検査の規約を `docs/dev-rules/coding-rules.md` に書く

- 提案: 次の 1 行を足す。
  - 値を取るオプションは、値を受け取る分岐で「値が無い」と「値が空」を同じ引数不正として拒否する。単体テストは、値を取るすべてのオプションに空文字を渡して確かめる。
- 根拠: `learnings/20261118_023215_empty-option-value-must-be-rejected-where-value-is-read.md`
