# 「10 秒以内に復帰する」Scenario が経過時間を合否にしている

- uc_id: 65b09d93(slot runner の実体スクリプトを割り当てる / assign-slot-runner-scripts)
- 起票 stage: S2 test-scaffold
- 種別: 仕様と利用者決定の不一致(S2 の blocker ではない。S4 / S6 で step を実装する前に扱いを決める)

## 仕様の記載

- spec.md E2E 完了条件(異常系)「--help に応答しない runner の問い合わせは待機上限で打ち切られ 10 秒以内に復帰する」の Then 1 行目: 「終了コード 0 で、起動から終了までの経過時間は 10 秒以内である(契約 runner_help_probe.response_time_budget の問い合わせの上限 9.2 秒に、数行の設定の検査の時間を加えた、この入力での確認)」
- tier-facade.md ティア完了条件「validate-config_sh_feature-flag は --help に応答しない runner を待機上限で打ち切り両 slot 未応答でも 10 秒以内に復帰する」の Then 1 行目: 同じ文言
- どちらの Given も「--help を受けると 30 秒応答しない(sleep する)スタブ runner」を両 slot に割り当てる

## 実装で判明した事実

- 利用者決定(2026-11-18、CLAUDE.md「性能で見るのは『ムダな処理がないこと』だけ」): 時間を確かめるテストは書かない。同日のコミットで、時間を確かめるテストと重いテストの仕組みを削除済み
- 2 つの Scenario は、Then 1 行目が経過時間を合否にしている。また、問い合わせが待機上限まで待つため、1 回の実行で実時間を数秒(slot ごとの待機上限 × 2)使う
- 一方、この Scenario の残りの Then(両 slot の warn 行が出る / `<slot>_runner_if_version` が `-` / 終了時点で runner のプロセスが残っていない)は、時間ではなく「待機上限で打ち切って止めた」ことの観察結果で、時間を測らずに判定できる
- 待機上限そのもの(上限に達したら止めて未応答と扱う)は、既存の単体テスト `facade/test/gateway/runner_probe.bats`(待機上限 1 秒を渡すテスト)が判定している
- S2 では転写ルール(意訳・削除の禁止)に従い、feature 本文は仕様のまま転写した。step は skeleton(not implemented)で、経過時間の判定はまだ書いていない

## 提案

- S8(feedback): 2 つの Scenario の Then 1 行目から経過時間の条件を外し、「待機上限で打ち切られ、終了コード 0 で終わる」と述べる形に改める変更要求を出す(Scenario 名の「10 秒以内に復帰する」も同様)。プロセスが残らないこと・warn 行・`-` の判定は残す
- S4 / S6(仕様が改まるまでの step の扱い): 次のどちらかをオーケストレータが決める
  - 推奨: 経過時間は判定せず、残りの Then(warn 行 / `-` / プロセスが残らない)だけを実体で判定する。step のコメントに本 issue のパスを書く。待機時間を短くするため、問い合わせの待機上限をテストから差し替えられるか(契約 runner_help_probe の値を変える口が実装にあるか)は S4 で確認する
  - 代替: 仕様が改まるまで、この 2 Scenario を本 UC のゲートの対象から外す(保留として記録する)
