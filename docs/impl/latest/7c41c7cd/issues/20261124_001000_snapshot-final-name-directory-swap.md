## 1. 仕様の約束

CLI コマンド契約 `config_input_rules.snapshot.work_name`(判断記録 spec-decision-041)は、
X を置き換えない mktemp(BSD 系)で作業名を予測できることを受け入れている。その代償を次のように限っている。

> 影響は複製の失敗までで、複製の内容を読まれたり、すり替えられたりはしない

また、複製は作業名から最終名へ「同一ディレクトリ内で rename する」と定めている。

## 2. いまの実装で起きること

`facade/src/repository/job_map_repo.sh` は `mv -- "$work" "$JOB_MAP_REPO_SNAPSHOT"` で最終名へ移す。

| 最終名の場所に先にあるもの | `mv` の動き | 結果 |
|---|---|---|
| 何も無い | 最終名へ rename する | 約束どおり |
| 別の利用者が置いたディレクトリ | ディレクトリの**中へ**移す(手元の macOS で再現した) | 複製は他人のディレクトリの中に入る。最終名はそのディレクトリのまま |
| ディレクトリへのシンボリックリンク | リンク先のディレクトリの中へ移す | 同上 |

置いた利用者はそのディレクトリやリンクの持ち主なので、読み手が最終名を開く前に、
最終名を自分の用意したファイルへ差し替えられる。この場合、読み手は差し替えた内容を読む。
これは約束の「すり替えられたりはしない」に反する。

前提として、X を置き換えない mktemp を使う環境(作業名と最終名を予測できる)が必要になる。
本番の Linux(GNU mktemp)では X が乱数になるため、実際に狙える場面は小さい。

## 3. 直し方(仕様は変えない。実装を約束に合わせる)

S4 の実装担当が、次のどちらか、または両方で直す。

- 移す前に、最終名に何かあれば(ディレクトリ・リンク・ファイルのどれでも)複製の失敗
  (`config snapshot failed`、終了コード 6)にする。そのうえで、最終名の中へ移す動きにならない移し方にする
- 作業名を読み取り用に開いておき、以後はそのファイル記述子だけから読む

`mktemp` で複製を作るほかの読み手(feature flag の検証・ジョブマップの検証など、同じ複製の定めを使う箇所)にも同じ形があれば、同じく直す。
再現テスト(最終名の場所に先にディレクトリを置くと、終了コード 6 になり、すり替えた内容を読まない)を bats に加える。

## 4. 利用者に伝えること

判断記録 041 で受け入れた代償は「複製に失敗するだけ」だった。実装を直せば、この前提は事実どおりになる。
最終確認(S9)で、直したことと再現テストを示す。
