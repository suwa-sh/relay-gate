# 同じ形の欠陥は、機能の名前ではなく操作で探す

## 何が起きたか

入力の一時複製の欠陥(確定名のディレクトリの中へ `mv` が移してしまう)を 4 回目の実装で直した。
このとき「同じ形のほかの箇所」も探したが、成果物を確定名へ移す箇所は見つからなかった。
同じ形の欠陥が、次の独立した検証で直すべき指摘として見つかり、やり直しが 1 回増えた(上限を 5 回へ延ばした)。

## 原因

- 課題の記述が、探す範囲を「`mktemp` で入力の複製を作るほかの読み手」と書いていた。
- 実装者はその範囲(入力の複製)だけを探し、「ほかに無い」と記録した。
- 欠陥の形は「`mv` の成功だけで確定名へ移せたと判断する」であり、入力の複製に限らない。

## 回避方法

- 欠陥を直すときは、原因になった操作(今回は `mv`)を、対象のディレクトリ全体で検索する。
- 5 回目はこの探し方に変え、`mv` を使う箇所が 2 か所だけであることを確かめた。

## 次回の対応

- 課題に「同じ形の箇所も直す」と書くときは、探す範囲を機能の名前ではなく、操作(コマンド・関数・書き方)で書く。
- 実装の完了の記録には、探した語と範囲、見つかった件数を書く。
