# mktemp のテンプレートは、X が末尾に無いと名前が固定になる環境がある

## 何が起きたか

- 入力の一時複製の作業名を、仕様の例のとおり `mktemp "${TMPDIR:-/tmp}/relay-gate-XXXXXX.part"` で作っていた。
- 開発機(macOS)では、作業名が毎回 `relay-gate-XXXXXX.part` のままになった。
- blue と green の slot runner がほぼ同時に動くと、後から来たほうの複製が失敗した。
- 単体テストと機能のシナリオ(1 プロセスずつ動く)では出なかった。全機能を通した結合テストの 1 件が、約半分の確率で失敗して、はじめて分かった。
- 前の機能でも、検証者が 2 つの実行を同時に流したときに、同じ原因で単体テスト 1 件が失敗していた(当時は「環境の事情」と分類した)。

## 原因

- BSD 系の mktemp は、テンプレートの末尾にある X の並びだけを置き換える。末尾以外の X は文字のまま残る。
- GNU の mktemp は、X の並びの後ろに接尾辞があっても置き換える(今回の作業では Linux で実行しておらず、未確認)。
- 仕様は「最終名を先に確保しない」とも定めるため、末尾に X を置いた名前を作ってから `.part` を付ける回避が使えなかった。

## 回避方法

- テンプレートを `relay-gate-<プロセスの番号>-XXXXXX.part` にした。プロセスの番号は `BASHPID` を、コマンド置換の外で取る(コマンド置換の中で取ると、サブシェルの番号になる)。
- mktemp が返した名前を、移し替えずにそのまま使う。名前の確保は mktemp の 1 回の操作(既にあれば失敗)のままにする。
- 単体テストに「2 つのプロセスが同じ一時ディレクトリで同時に複製を持つ」を足した。直す前に失敗することを確かめてから直した。

## 次回の対応

- mktemp のテンプレートを書くときは、X を末尾に置く。接尾辞が要るときは、名前を分ける別の要素(プロセスの番号など)を入れる。
- 一時ファイルを作る処理には、「同じ一時ディレクトリで 2 つのプロセスが同時に動く」単体テストを最初から書く。
- 同時に流したテストが一時ファイルの名前でぶつかったら、「環境の事情」と決める前に、名前の作り方を確かめる。
- 仕様の例にあるコマンドでも、開発機と実行環境で動きが同じかを 1 回実行して確かめる。
