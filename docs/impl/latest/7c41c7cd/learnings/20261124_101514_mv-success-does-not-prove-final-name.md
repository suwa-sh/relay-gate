# mv の成功は「確定名へ移せた」ことを証明しない

## 何が起きたか

一時ファイルへ書いてから確定名へ `mv` で移す処理が 2 か所あった(入力の一時複製、解決できないときの成果物)。
どちらも、確定名に先にディレクトリ(またはディレクトリへのリンク)があると、次のようになった。

| 場所 | 結果 |
|---|---|
| 入力の一時複製 | 複製が他人のディレクトリの中へ入った。置いた利用者は、読み手が開く前に内容を差し替えられた |
| 成果物 | 成果物がそろっていないのに、完了の印(exitcode.txt)を公開して終了コード 2 を返した |

## 原因

- `mv A B` は、B がディレクトリのとき `B/A` へ移して終了コード 0 を返す。
- 実装は `mv` の終了コードだけで「確定名へ移せた」と判断していた。
- 単体テストは、確定名に何も無い場合と、書き込みに失敗する場合だけを確かめていた。

## 回避方法

- 移す前に、確定名が「何も無い」か「置き換えてよい種類(リンクでない通常のファイル)」であることを確かめる。
- 移した後に、確定名が「リンクでない、自分の持つ通常のファイル」であることを確かめる。違えば失敗にする。
- 確認と移動の間に置かれたディレクトリの中へ移ったファイルは、その中の名前だけで消す。先に置かれていたものには触れない。
- テストは、確定名にディレクトリ・ディレクトリへのリンク・切れたリンクを置いて、実プロセスで確かめる(コマンドの差し替えは使わない)。

## 次回の対応

- 「一時名 → 確定名」の移動を新しく書くときは、移動の前後の確認を持つ共通の関数を通す。`mv` を直接書かない。
- 仕様が結果(すり替えられない / そろえられなければ公開しない)を約束している箇所は、確定名に先客がある場合のテストを最初から書く。
