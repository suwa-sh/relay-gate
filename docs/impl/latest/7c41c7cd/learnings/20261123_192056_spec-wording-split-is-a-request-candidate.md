# 仕様の 2 か所が同じ状態に別の文言を定めていたら、実装が困らなくても要求の候補に出す

## 何が起きたか

- 「あるが読めないジョブマップ」の報告が、読み手によって 2 通りあった。feature flag の検証は「見つからない」、ジョブマップの検証と slot runner は「読めない」と報告する
- 初回の整理では「どちらも仕様どおりで、実装で困った事実は無い」として、要求にしなかった。記録の末尾の注にだけ書いた
- 最後の確認で、利用者が「文言をそろえる要求を足す」と回答した。下書きと記録を作り直し、確認が 1 往復増えた

## 原因

- 要求にするかどうかを「実装が止まったか・困ったか」で決めた。仕様どうしの食い違い(機能の仕様と、全コマンド共通の規約)は、実装が両方を満たせる限り拾わなかった
- 同じ食い違いは、1 回目の独立した検証で slot runner の側の指摘として現れていた。実装を直して終わりにし、同じ書き分けが残る別の読み手を仕様の問題として扱わなかった

## 回避方法

- 独立した検証が「共通の規約と食い違う」と指摘したら、実装を直すだけでなく、同じ書き分けを明記している仕様の箇所を探す
- 見つかったら、重さを「作業を止めない」とした要求の候補として、案と推奨を付けて下書きに入れる。出すかどうかは利用者が決める

## 次回の対応

- 仕様の 2 か所が同じ状態に別の文言・別の扱いを定めている場合は、初回の整理で要求の候補に入れる
- 「実装で困っていないから要求にしない」と判断するのは、食い違いが無い場合(片方にしか記述が無い場合)に限る
