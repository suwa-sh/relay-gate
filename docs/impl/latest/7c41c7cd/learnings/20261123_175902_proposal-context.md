既存の CLAUDE.md と dev-rules は変更していない。取り込むかどうかは利用者が判断する。

## 提案 1: 開発機と実行環境で、コマンドの動きが違う点を書く

追加する場所: 「プロジェクト固有(bootstrap が確定)」の箇条書き。

```markdown
- 開発機は macOS(BSD 系のコマンド)、実行環境は Linux(GNU のコマンド)。動きが違うコマンドは、両方で同じ結果になる書き方を選ぶ
  - `mktemp` のテンプレートは、X の並びが末尾に無いと macOS では置き換わらない(名前が固定になる)。接尾辞が要るときは、プロセスの番号(`BASHPID`)を名前に入れる
  - 一時ファイルを作る処理には、同じ置き場で 2 つのプロセスが同時に動く単体テストを書く
```

- 理由: 仕様の例のとおりに書いた `mktemp` が、開発機で名前の衝突を起こした。結合テストまで見つからず、実装を 1 回やり直した。
- 根拠: `docs/impl/latest/7c41c7cd/learnings/20261123_175902_mktemp-template-needs-trailing-x-or-pid.md`

## 提案 2: 読めないジョブマップの報告は、読み手で文言が違うことを書く

追加する場所: 同じ箇条書き。

```markdown
- あるが読めないジョブマップの報告は、読み手で文言が違う(どちらも仕様どおり。機能ごとに問い直さない)
  - 検証コマンドの feature flag の検証: `job map not found`
  - 検証コマンドのジョブマップの検証と slot runner: `config file is not readable`
```

- 理由: この機能の実装中に 2 回、「実装の食い違いではないか」と観察として記録された。仕様を読むと、どちらも明記されている。
- 文言をそろえると利用者が決めた場合は、この提案の代わりに仕様への要望を 1 件足す。
