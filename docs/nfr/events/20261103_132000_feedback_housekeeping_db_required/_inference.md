# 推論根拠サマリ: 20261103_132000_feedback_housekeeping_db_required

## 入力

- USDM: SPEC-014-07 を変更(ハウスキープ設定の管理 DB 接続参照名は、RAPID_CROSSCHECK_MODE が off 以外の設置と、確報クロスチェックを使う設置では必須。無い・空なら設定エラーで非 0 終了し何も削除しない。省略できるのは管理 DB を一切使わない設置だけ)
- USDM: SPEC-014-08(管理 DB に接続しない振る舞い)をその設置に絞った。SPEC-014-04 に、off でも確報クロスチェックを使う設置では確報比較依頼を保持日数で削除する旨を追加
- RDRA: 情報「ハウスキープ設定」と条件「ハウスキープの削除判定」の説明を更新

## 判断

- 前回(2026-11-03 午前)の NFR 追従で B.3.3.1 と F.1.2.1 に入れた記述を、上記の条件と照合した
- B.3.3.1(ストレージ拡張性): 「off で接続参照名が無い設定では確報比較依頼が日次で増え続ける」は、確報クロスチェックを使う設置では接続参照名が必須となり設定エラーで止まるため成り立たなくなった。確報比較依頼は保持日数で削除され、保持日数分の見積もりに収まる。管理 DB を一切使わない設置では新たな管理 DB の行は生まれないため、残るのは off 以外の期間に作られた実行の管理 DB の行と成果物だけ(有限)とした。グレード(スケールアップ)は変わらない
- F.1.2.1(通信プロトコル): ハウスキープ設定の接続参照名が off で一律に省略できると読めるため、必須条件と省略できる設置を明記した。グレードは変わらない
- バックアップ・認証・アクセス制御・監査の記述は、必須条件の変更に依存しないため変更しない
