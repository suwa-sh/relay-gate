# 推論根拠サマリ

## ハウスキープ設定の接続参照名の必須化(CR-9d2e6c41-001、causal)

- 根拠: 前段の要求仕様の変更(SPEC-014-04 / 07 / 08)、RDRA の情報「ハウスキープ設定」と条件「ハウスキープの削除判定」の説明更新、NFR B.3.3.1 / F.1.2.1 の説明更新
- 判定: latest の SP-027 / SP-028 / BC-005 の語 / CM-013 / E-028 は、直前の更新で「off なら接続参照名を省略でき、そのとき管理 DB に接続しない」と書いていた。確報クロスチェックを使う設置では off でも必須、必須なのに欠けたら設定エラーで何も削除しない、という今回の条件と食い違うため、最小限で直した(changed)
- 追加で直した箇所: tier-ops の usecase は「削除待ちの置き場の残りの無条件削除」を最初の段としていた。設定エラーなら置き場の中身も消さないため、設定の検査をその前に置いた
- 同じ理由で、BC-006 の語「削除待ちの置き場」の「次回の実行で無条件に削除する」に、設定の検査を通った実行に限ることを追記した
- 判定に使う情報: 接続参照名が必須かどうかは RAPID_CROSSCHECK_MODE と確報クロスチェック worker 設定の有無で決まる。確報クロスチェック worker 設定は BC-005(適用構成)の語として既にあるため、CM-013 の説明に加えるだけで足り、新しいコンテキスト間の関係は要らない
- nullable: 管理 DB を一切使わない設置では省略できるため、E-028 の接続参照名は nullable: true のまま
- 変更しない: 削除の所有と専用ロール(CTR-008)、削除順序とアダプタ(LP-025 / LP-026)、BC-006 の境界、CM-009〜012、off の期間の成果物だけの判定規則と warn の規則
- 仕様で確定するもの: 確報クロスチェック worker の設定があるとみなす判定方法(既存の確報系コマンドの判定と揃える)、設定エラーの終了コード、キー名、warn の文言
