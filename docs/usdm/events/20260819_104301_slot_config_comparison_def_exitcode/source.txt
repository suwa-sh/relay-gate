## CR-6078c4ed-010: respond-foregroundの終了コードを透過にしrelay-gateエラーを分離する（要約）

- severity: spec-gap
- related_ids: [REQ-002, SPEC-002-01]
- 内容: USDM・UC spec は exitcode.txt の透過を規定する一方、CLI コマンド契約は非 0 を一律 1 へ
  丸める写像を定義しており、業務ジョブの終了コード分岐が既存ジョブ直接実行時と互換にならない。
  業務ジョブの失敗と relay-gate 自身のエラーも同じ 1 で区別できなかった。
- 確定した採用案: foreground の exitcode.txt 値を 0 を含む全値そのまま透過する。relay-gate 自身の
  エラーは専用の退避終了コードへ分離する（採用値: 実行結果未確定・取得不能・中止済み = 125、
  バリデーションエラー = 124。bash 予約コード 126 / 127 との衝突を避けるため、候補の 126 に代えて
  124 を採用した）。relay-gate エラー時の標準エラーは foreground の stderr.log の内容（取得可能な
  場合）と relay-gate のエラー内容（原因と次アクション）を併記する。UNKNOWN を推測で FAILED 相当の
  終了コードへ変換しない方針は維持する。
