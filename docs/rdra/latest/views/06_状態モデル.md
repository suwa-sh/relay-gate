# 状態モデル

RDRA システム内部レイヤー。状態モデルごとの状態遷移。遷移ラベルは UC。

## background slot実行状態（実行管理）

```mermaid
stateDiagram-v2
  s1 : STARTING
  s2 : RUNNING
  s3 : SUCCEEDED
  s4 : FAILED
  s5 : ABORTED
  s6 : UNKNOWN
  [*] --> s1
  s2 --> s3 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s2 --> s4 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s2 --> s5 : 対話確認のうえblue background実行をABORTEDへ遷移させる
  s2 --> s5 : 対話確認のうえgreen background実行をABORTEDへ遷移させる
  s3 --> [*]
  s4 --> [*]
  s5 --> [*]
  [*] --> s1 : execution-spec.jsonの実行設定を保ったまま再実行する
  s1 --> s2 : background roleを起動する
  s1 --> s6 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s2 --> s6 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s6 --> s3 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s6 --> s4 : background実行の未完了・非0終了・速報比較異常を定期検知する
  s6 --> s5 : 対話確認のうえblue background実行をABORTEDへ遷移させる
  s6 --> s5 : 対話確認のうえgreen background実行をABORTEDへ遷移させる
```

| 状態 | 遷移UC | 遷移先状態 | 説明 |
|---|---|---|---|
|  |  | STARTING | background roleの起動を受け付け、accepted_atを記録して起動試行を開始する |
| RUNNING | background実行の未完了・非0終了・速報比較異常を定期検知する | SUCCEEDED | hang-detectorがexitcode.txtの終了コード0を検知し完了と判定する |
| RUNNING | background実行の未完了・非0終了・速報比較異常を定期検知する | FAILED | hang-detectorがexitcode.txtの非0終了コードを検知し異常と判定する |
| RUNNING | 対話確認のうえblue background実行をABORTEDへ遷移させる | ABORTED | 停止確認済みのblue background実行を運用者の対話確認を経て中止状態へ明示的に遷移させる(blue中止フロー) |
| RUNNING | 対話確認のうえgreen background実行をABORTEDへ遷移させる | ABORTED | 停止確認済みのgreen background実行を運用者の対話確認を経て中止状態へ明示的に遷移させる(green中止フロー) |
| SUCCEEDED |  |  | 正常終了としてforeground結果の応答・完了通知・障害調査のための実行結果を確定する |
| FAILED |  |  | 異常終了としてforeground結果の応答・ハング監視での検知対象となる実行結果を確定する |
| ABORTED |  |  | 中止済みとして実行系譜の追跡対象となる実行結果を確定する |
|  | execution-spec.jsonの実行設定を保ったまま再実行する | STARTING | 再実行では元のexecution-spec.jsonとslot別実行設定で新しいrun_idの実行を新規作成しparent_run_idで元run_idに関連付け、起動受付としてSTARTINGから開始する。元の実行のレコードと履歴は変更しない(background側リランフロー) |
| STARTING | background roleを起動する | RUNNING | プロセスの起動を確認しstarted-at.txtを記録して実行中と判定する |
| STARTING | background実行の未完了・非0終了・速報比較異常を定期検知する | UNKNOWN | 起動受付後にtimeoutや結果取得不能で起動可否を確定できない場合、推測でFAILEDを確定せず結果不明として扱う |
| RUNNING | background実行の未完了・非0終了・速報比較異常を定期検知する | UNKNOWN | timeoutや結果取得不能で実行結果を確定できない場合、推測でFAILEDを確定せず結果不明として扱う |
| UNKNOWN | background実行の未完了・非0終了・速報比較異常を定期検知する | SUCCEEDED | 実結果（exitcode.txt）を回収し終了コード0を確認して正常終了へ確定する |
| UNKNOWN | background実行の未完了・非0終了・速報比較異常を定期検知する | FAILED | 実結果（exitcode.txt）を回収し非0終了コードを確認して異常終了へ確定する |
| UNKNOWN | 対話確認のうえblue background実行をABORTEDへ遷移させる | ABORTED | 結果不明のblue background実行を運用者の対話確認を経て中止状態へ確定する(blue中止フロー) |
| UNKNOWN | 対話確認のうえgreen background実行をABORTEDへ遷移させる | ABORTED | 結果不明のgreen background実行を運用者の対話確認を経て中止状態へ確定する(green中止フロー) |

## 速報比較依頼状態（速報クロスチェック管理）

```mermaid
stateDiagram-v2
  s1 : REQUESTED
  s2 : CLAIMED

  s4 : SUCCEEDED
  s5 : FAILED

  s1 --> s2
  s2 --> s1
  s2 --> s3 : 速報クロスチェックを実行し差分を検知する
  s3 --> s4 : 速報クロスチェックを実行し差分を検知する
  s3 --> s5 : 速報クロスチェックを実行し差分を検知する
  s3 --> s6 : 対話確認のうえ速報比較依頼をABORTEDへ遷移させる
  s4 --> [*]
  s5 --> [*]
  s6 --> [*]
  [*] --> s1 : execution-spec.jsonの実行設定を保ったまま再実行する
```

| 状態 | 遷移UC | 遷移先状態 | 説明 |
|---|---|---|---|
|  |  | REQUESTED | blue/green runnerの完了通知を受けて速報比較依頼を作成する |
| REQUESTED |  | CLAIMED | workerが速報比較依頼を取得(lease取得)する |
| CLAIMED |  | REQUESTED | leaseが失効し、かつworkerが未着手の場合に依頼を差し戻し重複実行を防ぐ |
| CLAIMED | 速報クロスチェックを実行し差分を検知する | RUNNING | workerが速報比較の実行を開始する |
| RUNNING | 速報クロスチェックを実行し差分を検知する | SUCCEEDED | workerのexitcodeが0であることを確定する |
| RUNNING | 速報クロスチェックを実行し差分を検知する | FAILED | workerのexitcodeが非0であることを確定する |
| RUNNING | 対話確認のうえ速報比較依頼をABORTEDへ遷移させる | ABORTED | RUNNING中の速報比較依頼を運用者の対話確認を経て中止状態へ明示的に遷移させる(速報比較中止フロー) |
| SUCCEEDED |  |  | 速報クロスチェックの正常完了として速報比較結果を確定し保持する |
| FAILED |  |  | 速報クロスチェックの異常完了としてハング検知記録・運用者への通知の対象とする |
| ABORTED |  |  | 中止済みとして依頼の履歴を保持する |
|  | execution-spec.jsonの実行設定を保ったまま再実行する | REQUESTED | 再実行では新しいrun_idの速報比較依頼を新規作成しparent_run_idで元依頼に関連付ける。元依頼のレコード・状態・履歴は変更しない(background側リランフロー) |
