対象は、今回の差分更新で変えた 1 つの UC と CLI 契約。変えていない UC の判定は前イベントのまま。

| UC | 判定 | 根拠 |
|---|---|---|
| feature flag を設定する | ready | 9 キー以外のキーの値を読み取りの途中だけ作業用の領域に置いてよいこと、許す 3 条件、読み取りの範囲、及ぶ読み手が、CLI 契約の「読み取りの途中の一時的な保持」から 1 つに決まる。出力と終了コードは変わらない |

## 実装との関係

- 現在の実装は 3 条件を満たしている。実装とテストの変更は要らない。
- 3 条件のうち「空にする」「後に残すのはキー名だけ」は出力から観測できない。確認はコードの検証で行う。

## 残っている確認事項

- 補助コマンドへコマンドライン引数で行の内容を渡すことの可否は定めていない(利用者の決定に無いため)。現在の実装は一時ファイルを読ませており、影響は無い。
- 過去の判断記録の一部に、変更要求の識別子の形の文字列が残っている。今回の変更で入ったものではなく、今回は変えていない。
- 設定ファイルの読み手の一覧で、background 側をリランするコマンドに挙げたキーが「処理に使うキー」か「検査にも使うキー」かの書き分けは、今回より前からの記載のまま。今回の規則は「検査に使うキーは使うキーに含む」と定めたため、結果は左右されない。
