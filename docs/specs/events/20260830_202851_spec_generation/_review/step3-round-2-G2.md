## 確認済みで指摘なしの項目

- rapid-crosscheck-runner.sh / rapid-crosscheck-worker.sh / rapid-crosscheck-result.sh / validate-config.sh(--crosscheck-job-map / --target-catalog)の引数・オプション・終了コード・stdout 順序(#4 を除く)は cli-command-contract.yaml と一致
- テーブル名・列名・状態 enum(REQUESTED/CLAIMED/RUNNING/SUCCEEDED/FAILED/ABORTED、PENDING/ONE_COMPLETED/BOTH_SUCCEEDED/ANY_FAILED/REQUEST_CREATED、OK/NG/FAILED)は rdb-schema.yaml / ui-design.md と一致
- slot-completed / rapid-crosscheck-requests の channel 名・payload(SlotCompletedNotice 5 項目、RapidCrosscheckRequestMessage 4 項目)は asyncapi.yaml と一致(#11 の asyncapi 側の余剰プロパティを除く)
- dispatcher(条件付き INSERT + run_id 主キー + FOR UPDATE)と rerun(新 run_id で INSERT。元依頼は不変)の冪等条件は互いに矛盾しない
- RDRA トレーサビリティ: 6 UC の条件(速報クロスチェック有効判定 / 完了通知の系統独立 / 両系成功判定 / 比較依頼の一意性 / 依頼状態遷移規則 / claim 排他 / lease 失効判定 / 比較定義の選択 / 比較ツール終了コードの対応 / 速報結果の位置付け / 速報と確報のモデル分離 / 設定所有区分 / 適用側で定義する事項)、状態.tsv の遷移行(速報実行の完了状況 5 行、クロスチェック依頼 6 行)、情報.tsv の属性はすべて spec.md / buc-spec.md に反映されている
- 方針資料「RelayGate のしくみ」との整合: 完了通知は runner が exitcode.txt 公開後に自系統の公開 function で送る、依頼は両系成功時に一意作成、claim / lease 排他、RAPID_CROSSCHECK_MODE=off で管理 DB に触れない、速報結果をジョブスケジューラ応答に返さない、いずれも矛盾なし
