## 前提(これだけ知っていれば読める)

- USDM の正本は `docs/usdm/latest/requirements.yaml`(REQ 13 件 / SPEC 50 件 / 受け入れ条件 121 件。各 SPEC に Given/When/Then の受け入れ条件が 1〜8 件。feedback 20260905_todo_resolution で SPEC 5 件(SPEC-004-04 / 008-06 / 011-04 / 011-05 / 011-06)と既存 SPEC への受け入れ条件(SPEC-001-01 / 002-02 / 005-01 / 005-03 / 005-04 / 008-03 / 008-05 / 011-01)が追加され、feedback 20260907_todo_followup で SPEC 1 件(SPEC-005-06。受け入れ条件 4 件)と既存 SPEC への受け入れ条件(SPEC-005-01 に 1 件 / SPEC-005-02 に 3 件 / SPEC-010-01 に 2 件)が追加され、feedback 20260907_abort_consistency で既存 SPEC への受け入れ条件(SPEC-005-02 に 2 件 / SPEC-010-01 に 1 件 / SPEC-010-02 に 4 件)が追加された)
- UC Spec 側の対応づけは、各 UC の `spec.md`「関連 USDM」表(REQ ID / SPEC ID / 対応 BDD Scenario)から機械的に集計した。シナリオ名末尾の `(SPEC-xxx)` は除いて表記する
- UC ID(UC-01〜UC-32)は `uc-dependencies.md` / `_inference.md` と同じ番号
- 状態の定義: **covered** = 全受け入れ条件に対応する BDD シナリオが少なくとも 1 つの UC にある / **partial** = 受け入れ条件の一部だけに対応、または SPEC 本文の要素が UC Spec 側と食い違う / **uncovered** = 対応 UC が無い
- RDRA モデルの整合だけを問う受け入れ条件(SPEC-008-03 の「バリエーション『監視状態』と状態モデルが同じ 6 値」、SPEC-011-05 の「外部システム一覧に管理 DB が無い / リモート実行ホスト(SSH)が残る」)は BDD シナリオの対象外で、UC spec の「関連 RDRA モデル」表と cross-cutting(契約 `shared_rules.state_codes` / 依存表の外部システム表記)で照合する。振る舞いの受け入れ条件を持たない SPEC は対応 UC が無いため定義どおり uncovered と数える
- 本ファイルは第 3 ラウンド(Step6.5 反証レビュー round-1 の修正)後の集計を起点に、本イベント(feedback 20260905_todo_resolution の差分更新。`_review/change-brief.md` D1〜D12 / U1〜U11)後の全 32 UC の spec.md「関連 USDM」表と `requirements.yaml`(REQ 13 / SPEC 49 / 受け入れ条件 105)を突き合わせて再集計した。さらに本イベント(event 20260907_024000。feedback 20260907_todo_followup の差分更新。`_review/change-brief.md` D1〜D3)で、`requirements.yaml`(REQ 13 / SPEC 50 / 受け入れ条件 115。`grep -c` で数え直し)と追加受け入れ条件の配置 UC(D1-5 / D2-5)を突き合わせて再集計した。さらに本イベント(event 20260907_131000。feedback 20260907_abort_consistency の差分更新。`_review/change-brief.md` D1〜D5)で、`requirements.yaml`(REQ 13 / SPEC 50 / 受け入れ条件 121。`grep -c` で数え直し)と追加受け入れ条件の配置 UC(D5)を突き合わせて再集計した
