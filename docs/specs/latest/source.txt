CR-f4c8b261-001(infra 直接所有。spec は保守的 closure。利用者承認済みの直し方): 管理 DB の接続先の参照名が同じ管理 DB に解決されることを、CLI 契約にも前提として書く。
- 問題: 確報クロスチェックの設定ファイルは実行ホスト(確報 runner)と DB セグメント(確報 worker)に別の元ファイルで配る。2 つのファイルの FINAL_DB_CONN_REF が別の DB に解決されると、設定の検査をすべて通っても worker は runner の依頼を取得できず、確報ジョブが完了しない。CLI 契約 conventions.credentials は参照名を列挙し、解決を適用側の運用手順に委ねるとだけ書いており、すべての参照名が同じ 1 つの管理 DB に解決されるという前提が無かった。
- 書いた前提(契約 conventions.credentials):
  - 管理 DB は 1 つで、すべての管理 DB 接続参照名(RAPID_DB_CONN_REF、実行ホストと DB セグメントそれぞれの FINAL_DB_CONN_REF、HANG_DB_CONN_REF、HOUSEKEEP_DB_CONN_REF)は同じ 1 つの管理 DB に解決される。
  - 理由: 確報 runner が登録した確報比較依頼を、確報 worker が同じキューから取得するため。
  - 条件は参照名の文字列が同じことではなく、解決先(接続先の DB)が同じこと。HOUSEKEEP_DB_CONN_REF は専用 DB ロール housekeep_del で業務用ロールとは別のロールを指すが、解決先の DB は同じ。
  - 解決先が同じことは導入する側が確かめる。構築手順の配置時の検査は設定ファイルの存在確認だけで、relay-gate のコマンド(validate-config.sh と各読み手の起動時の検査)も解決先を検査しない。
- 揃えた箇所: 契約 config_files の final-crosscheck.env の note と FINAL_DB_CONN_REF、rapid-crosscheck.env の RAPID_DB_CONN_REF、hang-detector.env の HANG_DB_CONN_REF、housekeep.env の HOUSEKEEP_DB_CONN_REF。6 UC の tier md の設定キー表(速報比較依頼を claim する / 速報クロスチェック runner へ完了通知を送信する / 確報比較依頼を登録して終端状態まで待機する / 確報比較依頼を claim する / background 実行の経過時間と終了状態を判定する / 保持日数を過ぎた終了済みの実行と確報比較依頼を判定する(キー表の直下の説明))。
- 足さないもの: 新しい検査・error 文言・終了コード・BDD(relay-gate は解決先を検査しないため)。
